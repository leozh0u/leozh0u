# Hi, I'm Leo

CS at Rice, originally from Auckland. I work on backend and infrastructure, mostly in Go and Python.

The biggest thing I have built is [blundernet](https://github.com/leozh0u/blundernet), live at [blundernet.com](https://blundernet.com) with about 120 people on it. It is 3.25 million chess puzzles you can filter by rating, theme and phase, plus bots to play against. There is also a classroom mode, where a coach pushes a position to the room and the answers come back grouped by move with a count. A review judges every move by the winning chances it cost rather than by centipawns, brilliant down to blunder, and it takes a game pasted from any site. The board can be read without being seen: every position is written out for a screen reader, and a blindfold toggle hides the pieces without taking them off the board. Drawing a random one out of six million rows took 1.4 seconds; a precomputed grid and a stored shuffle key got that to 0.9ms. The Go API holds no state. Live games sit in Redis, inference runs on queue-fed workers so a slow move never blocks a request, and the AWS stack is in Terraform. The engine is [blundernet-engine](https://github.com/leozh0u/blundernet-engine), a small residual net with PUCT search written first in Python and then in C++ through pybind11, retrained on a schedule without me. It plays around 1000 Elo, which is bad at chess and about right for a network this size.

What I am building now is [vestigo](https://github.com/leozh0u/vestigo), an agent that works out where a photograph was taken, with a site for it at [vestigo.earth](https://vestigo.earth). Every claim it makes has to cite its evidence, and it is scored on calibration rather than distance: a country it can defend is a better answer than a confidently wrong street address.
